# Cinema Backend System

`Cinema Backend System` — это backend API-сервис на Go для системы покупки билетов в кино. Проект моделирует не только базовые CRUD-операции, но и реальные бизнес-сценарии: бронь мест, оплату заказа, возврат билетов, отзывы с модерацией, бонусную систему и корректную работу при конкурентных запросах.

Это pet-проект, в котором акцент сделан именно на бизнес-логике и консистентности данных, а не только на структуре REST API.

## Что умеет сервис

- регистрация и авторизация пользователей
- управление профилем пользователя
- управление фильмами и сеансами со стороны администратора
- бронирование мест на сеанс
- редактирование и отмена брони
- оплата заказа деньгами и бонусными коинами
- возврат оплаченных билетов по бизнес-правилам
- управление способами оплаты
- отзывы пользователей на фильмы
- модерация отзывов администратором
- автоматический пересчёт рейтинга фильма
- защита критичных операций через транзакции и блокировки строк в БД

## Реализованная бизнес-логика

Проект покрывает несколько важных сценариев, характерных для реального билетного сервиса:

- пользователь может забронировать конкретные места на сеанс
- занятые места становятся недоступны для других пользователей
- бронь можно изменить до оплаты
- бронь можно отменить или удалить после истечения времени жизни
- при оплате можно использовать бонусные коины
- после успешной оплаты пользователю могут начисляться бонусы
- возврат зависит от времени до начала сеанса
- отзыв можно оставить только после оплаченного заказа
- рейтинг фильма меняется только после модерации отзыва

## Конкурентные запросы и консистентность

Одна из ключевых задач проекта — корректная работа в ситуациях, когда несколько пользователей одновременно совершают действия в системе.

Для этого в критичных местах используются:

- транзакции базы данных
- блокировки строк через `SELECT ... FOR UPDATE`

Это нужно для защиты от проблем вроде:

- два пользователя одновременно пытаются занять одно и то же место
- один и тот же заказ оплачивается дважды
- одновременно выполняются списание и возврат средств
- баланс пользователя затирается при параллельных обновлениях
- рейтинг фильма пересчитывается некорректно при одновременном аппруве нескольких отзывов

Транзакции и блокировки применяются в сценариях:

- создание брони
- обновление брони
- оплата заказа
- возврат заказа
- обновление баланса пользователя
- модерация отзывов и пересчёт рейтинга фильма

```text

├── internal/
│   ├── handlers/      # HTTP-обработчики
```

## Локальный запуск

### 1. Клонировать репозиторий

```bash
git clone https://github.com/egoruser11/cinema_baclend_system.git
cd cinema_baclend_system
```

### 2. Поднять PostgreSQL

Если используешь Docker Compose:

```bash
docker compose up -d
```

### 3. Проверить настройки подключения к БД

Сейчас DSN задан напрямую в `internal/utils/helpers.go`:

```go
const DbConfig = "host=localhost user=user password=password dbname=mydb port=5432 sslmode=disable"
```

Перед запуском нужно либо поднять PostgreSQL с такими параметрами, либо изменить строку подключения под свою локальную среду.

### 4. Запустить приложение

```bash
go run main.go
```

Сервис стартует на:

```text
http://localhost:8080
```

## Почему проект интересный

Этот проект показывает не только базовую работу с REST API, но и более прикладные backend-задачи:

- реализацию бизнес-правил
- работу с жизненным циклом заказа
- расчёт бонусов и возвратов
- защиту от race condition
- определение корректных границ транзакций
- пересчёт агрегатов вроде рейтинга фильма

Для pet-проекта это хороший пример перехода от “обычного CRUD-сервиса” к более предметно-ориентированному backend-приложению.
